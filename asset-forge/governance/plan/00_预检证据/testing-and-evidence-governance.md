# 测试与证据治理

## 证据分层

| 层级 | 定义 | 允许支撑的结论 |
|---|---|---|
| L1 项目契约 | 当前源码、schema、route、trainer mapping、preset、validator、可执行校验 | 当前训练器是否支持、字段和冲突规则 |
| L1 官方资料 | 模型/训练器官方文档、官方仓库、论文 | 架构事实、官方推荐、版本/兼容说明 |
| L2 观察样本 | 有 ID/URL/采集时间的 Civitai 元数据、项目真实运行记录 | 参数分布、常见做法、候选起点 |
| L3 推断/实验建议 | 由 L1/L2 推导但未实测的建议 | 明确标注的候选实验，不得写成事实 |

冲突优先级：目标页面宿主 validator/实际 trainer 契约 > 当前项目文档 > 外部观察。模型理论事实以官方资料/论文为准。

## 必须保留的证据

每个阶段至少保留：

1. preflight 或扫描范围说明；
2. 执行命令、工具、版本、时间与退出状态；
3. 原始事实定位或公开 URL；
4. 归一化结果和转换规则；
5. 失败、缺失、冲突和不适用样本；
6. 测试/评测结果；
7. stage completion gate；
8. evidence cleanup report。

## 测试矩阵解释

| 类型 | 本任务中的含义 |
|---|---|
| Unit | TOML/JSON/JSONL/Markdown 元数据解析、去重、计数、字段规则 |
| Contract | route/schema/trainer/validator 一致性；Civitai API 字段与响应边界 |
| Integration | 源码盘点→覆盖矩阵；元数据→证据统计→模板；候选文档→评测/迁移 manifest |
| Gray | README/preset/旧资产与当前源码对比；Civitai 观察与项目默认值对比 |
| Real | 受限公共 API/HTTP 请求和真实宿主 validator；不做 GPU 训练 |
| Zero-Short | 从空目录按 manifest 重建候选索引并完成只读校验；不写正式资产 |

## Civitai/外部网络限额

未在具体阶段报告中进一步收紧时，适用以下上限：

1. 只使用公开、无需 token 的 API/页面；禁止绕过登录、限流或访问控制。
2. 单次 probe 最多 10 个 HTTP 请求、60 秒、20 MB 原始响应。
3. 正式采样每批最多 100 个请求；每请求至少间隔 0.5 秒；失败最多指数退避重试 3 次。
4. 原始元数据总量软上限 500 MB，达到 400 MB 必须暂停并清理/去重。
5. 默认不下载图片或完整模型权重。
6. 如需读取 safetensors 头，必须先在阶段任务书登记，单文件 Range 响应上限 2 MB，总计不超过 50 MB；服务端若忽略 Range 并开始返回大文件，立即中止。
7. 保存 `modelId`、`modelVersionId`、公开 URL、抓取时间和字段，不保存 token、Cookie 或个人登录信息。

## Civitai 采样质量规则

1. 按训练器支持的 base model、网络类型和训练方向分层，不只按热度排序。
2. 同一模型的多个版本不得被误当成独立作者样本；统计中同时报告 model-level 与 version-level 数量。
3. 报告训练字段缺失率、异常值和未知值；缺失不得用默认值填充后伪装为观察。
4. 下载量/评分只用于发现和分层，不作为参数有效性权重。
5. 不复制长篇模型说明；仅保存结构化字段、必要短摘要和来源链接。

## 知识候选验证

1. 文件扩展名 `.md`，UTF-8。
2. 顶部包含 `Version`、`Scope`、`Evidence status`。
3. 每个精确数值、兼容结论或风险结论有来源卡或明确层级。
4. 禁止死链式内部引用；所有相对路径必须存在于候选集或标记为迁移目标。
5. 每篇至少一个评测场景；涉及参数的文档至少有一个“未知时不得编造”场景。

## 模板候选验证

1. 文件位于候选模板根目录顶层，扩展名 `.toml`，可由 `tomllib` 解析。
2. 必须有 `template_version`、`scope`、显式 `model_train_type`。
3. 不包含真实机器路径、用户名、token、数据集私密名；路径字段只能使用醒目占位符并在导入前要求替换。
4. 每个模板有相邻证据卡，记录来源样本、分布、选择理由、未知字段和适用方向。
5. 目标页面宿主 validator 结果不得为 `reject`；`skip` 不能算通过。

## 阶段完成门

结果只能是 `pass`、`pass-with-boundary` 或 `fail`。任何未授权 P0/P1、未运行硬校验、未记录来源的精确模板参数都会导致 `fail`。

## 清理与保留

- 永久保留：计划、来源登记、归一化数据、统计汇总、失败样本、最终候选、评测、manifest、hash、gate 报告。
- 可清理：重复 API 响应、HTML 临时页、调试日志、可再生中间缓存。
- 禁止进入暂存或迁移包：模型权重、图片、依赖缓存、Cookie/token、个人路径、未脱敏原始私密数据。
