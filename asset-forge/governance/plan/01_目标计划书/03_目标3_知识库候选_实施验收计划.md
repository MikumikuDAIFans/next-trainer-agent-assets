# 目标3：知识库候选实施验收计划

## 目标

按 G1 支持矩阵和 G2 证据分层编制候选知识库，使 Agent 能针对当前训练器的模型、训练方式、训练方向、参数、数据、评测与故障给出有边界且可引用的回答。

## 范围

- In scope: `04_知识库候选` 下的 Markdown、索引、来源卡和评测映射。
- Out of scope: 未支持模型的操作指南、无来源精确推荐、把经验起点写成保证结果。

## 前置条件

1. G1/G2 完成门通过。
2. 候选知识目录结构和命名规范冻结。

## 验收标准

1. 每个 first-class/conditional 模型族与页面至少有一篇基础指南；每个网络算法和训练粒度有适用性/限制说明。
2. 建立跨模型主题覆盖：数据准备、caption/tag/trigger、正则化、分辨率/bucket、曝光预算、LR/optimizer/scheduler、rank/alpha、缓存/精度、预览/评测、checkpoint 选择、故障与复现。
3. 建立训练方向覆盖：角色、风格、对象/概念、服装/姿态/表情/局部特征、修正/增强、slider/抑制等；若方向仅为数据方法或当前不支持，必须明确。
4. 每篇有 `Version`、`Scope`、`Evidence status`、检索别名、来源段和边界；参数建议区分 L1/L2/L3。
5. 每篇至少映射一个评测场景，全部内部链接可解析，敏感信息扫描为零。
6. `knowledge-coverage-matrix.csv` 显示模型×模式×主题×方向的覆盖状态和文件路径，不以文章数量替代覆盖证明。

## 测试要求

| 类型 | 要求 | 不适用说明 |
|---|---|---|
| Unit | Markdown 头、内部链接、来源 ID、别名、UTF-8、重复标题检查 | |
| Contract | 文档中的 pageTrainType/字段名与 G1/validator 一致 | |
| Integration | 候选索引→文档→来源→评测完整链路 | |
| Gray | 与现有正式知识比较，记录新增、替代、保留和文件名升级策略 | |
| Real | 对代表性问题执行 Agent/人工引用回放 | 不要求 GPU |
| Zero-Short | 从空索引重扫候选目录可重建文件清单和覆盖矩阵 | |

## 证据要求

lint 报告、覆盖矩阵、来源完整性报告、评测映射、现有资产差异报告和失败案例。

## 完成门

所有支持模式有基础覆盖；所有候选文档格式和引用检查通过；不存在无来源的精确参数或把 unsupported 写成 supported 的 P1 问题。

## 对后续阶段的解锁条件

知识候选可为模板证据卡和 Stage 4 评测提供稳定引用，但仍不得迁移。

## 残余风险

没有真实 GPU 对比时，主观图像质量结论只能作为实验建议，不能写成已验证结论。
