# 目标2：来源与样本证据实施验收计划

## 目标

建立可审计来源登记和受控 Civitai 样本库，回答哪些事实可用来写知识、哪些观察足以帮助选择模板起点，以及哪些模型族缺少公开实证。

## 范围

- In scope: 项目契约、模型/训练器官方仓库与文档、论文、Civitai 公共 API/页面元数据、必要且受限的 safetensors 头信息。
- Out of scope: 热度因果推断、复制长篇模型卡、图片采集、完整权重下载、使用账号或 token。

## 前置条件

1. G1 支持矩阵已冻结。
2. Civitai/API MVP probe 通过或给出明确替代路径。

## 验收标准

1. `02_来源与证据/source-registry.jsonl` 为每条来源记录 URL、标题、发布者/项目、版本/日期、访问时间、证据层级、适用主题和许可/引用注意事项。
2. 每个正式支持的模型族、训练后端和网络算法至少有一个 L1 项目契约和一个官方来源；无官方资料时明确标记缺口。
3. Civitai 采样按 base model、model-level 去重和训练方向分层：API 有足够数据时每个公开支持模型族目标不少于 30 个 model-level LoRA；不足时保留全量可得样本并报告不足，禁止补造。
4. 用于模板参数统计的“配置可用样本”必须含可追溯训练字段；每个页面目标不少于 8 个独立 model-level 样本，低于阈值时该页模板不得声称由 Civitai 分布支撑。
5. 原始记录、归一化记录、字段字典、去重方法、缺失率、异常值和采样偏差均有报告。
6. 每条样本保留公开 `modelId`、`modelVersionId`、URL、base model、网络/文件类型、trained words（如有）、训练参数（如真实存在）和采集时间；未知保持 null。

## 测试要求

| 类型 | 要求 | 不适用说明 |
|---|---|---|
| Unit | JSON/JSONL schema、ID 去重、null/缺失处理、统计计数 | |
| Contract | Civitai API 响应字段和分页/错误边界；官方 URL 可访问性 | |
| Integration | raw→normalized→统计→模板证据卡链路至少跑通一例 | |
| Gray | Civitai 参数分布与项目 preset/现有案例对比，记录差异不强行合并 | |
| Real | 公共 API 受限请求，遵守请求/大小/时间限制 | |
| Zero-Short | 仅凭 raw 数据和字段字典可重建 normalized 与统计摘要 | |

## 证据要求

请求日志、原始 JSON、归一化 JSONL、字段缺失报告、样本清单、来源登记和所有失败响应。

## 完成门

所有引用可追溯；模板样本阈值按页面明确为 `sufficient/insufficient`；不存在用下载量填补训练字段或把 unknown 变默认值的行为。

## 对后续阶段的解锁条件

G2 完成后，Stage 2/3 才能引用稳定来源与统计；不足模型族只能使用 L1 项目/官方基线并明确边界。

## 残余风险

Civitai 的 base model 分类与训练器模型族可能不完全对齐；必须保留映射表和不可映射记录。
