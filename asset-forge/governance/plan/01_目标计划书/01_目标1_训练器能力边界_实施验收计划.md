# 目标1：训练器能力边界实施验收计划

## 目标

从当前源码而非宣传文案穷举训练页面、模型族、后端引擎、网络算法、全量/参数高效模式、关键 feature flag 和可表达训练方向，回答“Next Trainer 当前到底支持什么”。

## 范围

- In scope: frontend training routes、`mikazuki/schema`、API run/mapping、预设、训练命令/脚本、导入 validator、相关测试和文档。
- Out of scope: 启动真实 GPU 训练、修改源码、把底层依赖可能性误写成 UI 正式支持。

## 前置条件

1. 预检和总控 GATE-00..03 已通过。
2. 训练器仓库保持只读。

## 验收标准

1. `01_训练器能力盘点/trainer-support-matrix.md` 对每个 route/schema/trainType 都列出模型族、训练目标、引擎、网络模块、命令入口、配置证据和支持等级。
2. `training-direction-taxonomy.md` 区分模型/架构、训练粒度、网络算法、数据目标和产物用途；角色、画风、特征、滑块等不再混为同一维度。
3. 形成 machine-readable `support-matrix.json`，每条至少有 `id`、`pageTrainType`、`modelFamily`、`backend`、`trainingGranularity`、`networkTypes`、`supportLevel`、`evidence`。
4. README、路由、schema、trainer、preset/validator 的所有冲突进入 `support-conflicts.md`，不得静默选择。
5. 每个结论标为 `first-class`、`conditional`、`backend-capable-ui-hidden`、`unsupported` 或 `unknown`。

## 测试要求

| 类型 | 要求 | 不适用说明 |
|---|---|---|
| Unit | 解析/去重支持矩阵并验证必填字段和唯一 ID | |
| Contract | route→schema→pageTrainType→trainer/validator 映射闭环 | |
| Integration | README 声明与源码矩阵生成完整差异表 | |
| Gray | preset/旧资产与当前 schema、validator 对比 | |
| Real | 只读加载真实 schema、调用无副作用 validator/current-config 接口或本地函数 | 不执行训练 |
| Zero-Short | 从空输出目录仅凭记录命令重建矩阵并得到相同计数 | |

## 证据要求

1. 源文件绝对路径、行号或符号名。
2. 扫描命令与输出清单。
3. machine-readable 矩阵校验报告。
4. 冲突和未知项清单。

## 完成门

支持矩阵中不存在无证据的 `first-class`；所有训练 route 均有归属；P1 冲突已解决或降级为 `unknown/conditional`。

## 对后续阶段的解锁条件

G1 完成门通过后，Stage 1 才可按真实支持模型族制定来源和 Civitai 采样层。

## 残余风险

运行时 feature flag 或外部插件环境可能使静态支持与本机可用性不同，必须在矩阵中单列 prerequisites。
