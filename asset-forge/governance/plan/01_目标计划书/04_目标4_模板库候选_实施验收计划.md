# 目标4：模板库候选实施验收计划

## 目标

为当前宿主 validator 可识别的训练页面编制证据透明、保守、可导入的候选 TOML，回答哪些配置可作为实验起点而不是复制即成功的“神参数”。

## 范围

- In scope: `05_模板库候选` 顶层 TOML、相邻证据卡、模板索引和 validator 记录。
- Out of scope: 当前页面不支持的模型模板、真实机器路径、未经 validator 的配置、只因 Civitai 热门而采用的参数。

## 前置条件

1. G1 页面/字段/validator 映射冻结。
2. G2 已标记各页面 Civitai 配置样本是否充足。
3. G3 提供必要参数与方向边界知识。

## 验收标准

1. 每个可识别页面至少一个 `conservative` 基线；只有当训练方向需要不同字段/参数并有证据时才添加角色、风格、概念或其他方向模板。
2. 每个 TOML 有 `template_version`、`scope`、显式 `model_train_type`，无真实机器路径或隐私。
3. 每个模板有 `.evidence.md`，列出项目默认、官方资料、Civitai 样本量/分布/缺失率、选择理由、未知项和适用方向。
4. 全部 TOML 可解析；宿主 validator 结果不是 `reject` 或 `skip`；normalized diff 被保存和人工复核。
5. 相互冲突字段、引擎专属字段、数据集独立 TOML 等规则与目标页面一致。
6. 无法通过 validator 或证据不足的草案移到 `research-rejected/` 并保留失败原因，不进入候选根目录。

## 测试要求

| 类型 | 要求 | 不适用说明 |
|---|---|---|
| Unit | TOML parse、必填元数据、路径/secret、文件名、重复 scope 检查 | |
| Contract | 每份模板对应有效 pageTrainType 和 schema/validator 字段 | |
| Integration | 证据统计→模板选择→validator→normalized diff 链路 | |
| Gray | 与 shipped preset、现有正式模板和 Civitai 分布对比 | |
| Real | 使用真实项目 validator 逐份校验 | 不执行 GPU 训练 |
| Zero-Short | 在空临时目录复制候选模板后仍能完成全量解析/校验 | |

## 证据要求

模板索引、证据卡、validator JSON/文本输出、normalized diff、拒绝草案和敏感信息扫描。

## 完成门

候选根目录零 parse/reject/skip；每个支持页面有基线或有“为什么无法安全出模板”的 P1 报告；任何经验参数均有层级和样本边界。

## 对后续阶段的解锁条件

G4 通过后，Stage 4 才可生成迁移映射和最终评测。

## 残余风险

宿主 validator 只能证明字段/冲突/页面契约，不证明训练效果；模板必须持续标注“起点、需验证”。
