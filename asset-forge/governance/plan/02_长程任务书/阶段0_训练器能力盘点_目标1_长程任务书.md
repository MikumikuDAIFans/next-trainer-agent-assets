### Phase 2: 支持矩阵与方向分类

- Purpose: 把代码事实归一化成可回答问题的领域模型。
- Outputs: `trainer-support-matrix.md`、`support-matrix.json`、`training-direction-taxonomy.md`。
- Completion criteria: 每个页面/模式有唯一 ID、支持等级、prerequisites、网络算法和证据；方向分类覆盖用户列举项并允许新增。
- Validation: JSON schema/唯一性检查；所有 route 和 README 声明均被映射或进入冲突表。
- Evidence: `06_评测与校验/evidence/stage-0/phase-2/`。
- Failure handling: 无法裁定的模式标 `unknown` 并保留 open question，不推断支持。

### Phase 3: 契约交叉验证与冻结

- Purpose: 用 preset、validator、测试和文档灰度对比矩阵。

- Completion criteria: 关键映射无未解释冲突；矩阵计数和验证命令可复现。
- Validation: route→schema→pageTrainType→trainer/validator 闭环；README diff；从空输出重建一次。
- Evidence: `06_评测与校验/evidence/stage-0/phase-3/`。
