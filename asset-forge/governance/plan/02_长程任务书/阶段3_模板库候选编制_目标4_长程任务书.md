## 目标

为每个宿主支持页面生成最小必要、证据透明并通过 validator 的保守模板集。

## 范围与约束

- In scope: 顶层 TOML、证据卡、索引、拒绝草案和 validator 报告。
- Out of scope: 神参数、机器路径、未支持页面、真实效果保证。
- Constraints: 每页先一个 conservative；方向模板必须有字段/参数差异证据；skip 不算 pass。

## 执行阶段

### Phase 1: 页面与模板覆盖设计

- Purpose: 确定哪些页面需要模板，避免重复和伪多样性。
- Outputs: `05_模板库候选/template-coverage-matrix.csv`、命名/元数据规范。
- Completion criteria: 每个 validator 页面有 baseline 计划或无法安全生成的阻断说明。
- Validation: pageTrainType 与 G1 映射闭环。
- Evidence: `evidence/stage-3/phase-1`。
- Failure handling: 不可识别页面不得生成候选 TOML。

### Phase 2: 参数选择与证据卡

- Purpose: 合并 project preset、官方说明、现有案例和充分的 Civitai 分布。
- Outputs: `05_模板库候选/*.toml`、`*.evidence.md`。
- Completion criteria: 所有值有选择理由；Civitai 不足时不声称统计支撑；无真实路径。
- Validation: TOML parse、字段审查、参数来源 trace。
- Evidence: `evidence/stage-3/phase-2`。
- Failure handling: 不确定字段从模板移除或移至 rejected，不凭想象补值。

### Phase 3: 宿主校验、归一化差异与冻结

- Purpose: 证明候选可被目标页面接受并观察 normalization。
- Outputs: validator report、normalized diff、`research-rejected/`、Stage 3 完成门。
- Completion criteria: 候选根目录零 reject/skip；冲突字段零；所有 normalization 变更已审查。
- Validation: 真实 `validate_config_import`/`training_config_validate`；空临时目录重跑。
- Evidence: `evidence/stage-3/phase-3`。
- Failure handling: reject/skip 模板移出候选并保留 failure report。
