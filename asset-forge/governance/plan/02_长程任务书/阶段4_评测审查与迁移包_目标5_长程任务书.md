## 执行阶段

### Phase 1: 全量结构与语义评测

- Purpose: 检查每个候选文件及关键 Agent 行为。
- Outputs: `06_评测与校验/evals/`、validation reports、failure corpus。
- Completion criteria: 每候选至少一个 eval；引用、未知拒答、冲突和参数边界覆盖；硬 lint 全过。
- Validation: deterministic checks + 代表性人工/Agent rubric。
- Evidence: `evidence/stage-4/phase-1`。
- Failure handling: P1 失败退回 Stage 2/3，不能在报告中豁免成 pass。

### Phase 2: 迁移预览与兼容计数

- Purpose: 让用户能精确审阅将来会发生什么。
- Outputs: `07_迁移包/migration-manifest.json`、`migration-preview.md`、hash、compat/eval count draft。
- Completion criteria: 每个源/目标/操作/hash/eval/版本策略齐全；旧实例播种策略明确。
- Validation: manifest schema、hash 重算、目标路径白名单、候选与正式 diff。
- Evidence: `evidence/stage-4/phase-2`。
- Failure handling: 目标冲突或覆盖风险为 P1，必须改文件名/计划。

### Phase 3: Zero-Short 与最终 readiness

- Purpose: 在不触碰正式仓的空目录中模拟候选集重建和校验。
- Outputs: zero-short report、最终 readiness、cleanup、Stage 4 完成门。
- Completion criteria: 临时目录按 manifest 重建并通过全部硬验证；正式仓库状态未变；结论 `awaiting-user-approval`。
- Validation: 全量重跑、文件数/hash 对比、Git status 基线对比。
- Evidence: `evidence/stage-4/phase-3`。
- Failure handling: 任一硬验证失败则 `not-ready`，不请求迁移授权。
